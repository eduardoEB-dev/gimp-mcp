# Working with paths supplied in a prompt

- When the user supplies file or folder paths, resolve and inspect them before asking what to do. Read the relevant files and look for applicable workflow or project instructions in the named folders. If a path is missing or an image cannot be opened, say what you were able to inspect.
- For routine folder and file inspection, use the available file tools such as Glob and Read. Use workspace-relative paths when possible and reserve shell commands for steps that need them.
- A prompt containing only a workflow folder under `Projects/Workflow/` and a project input path means apply that workflow to those inputs. Read the named workflow document first. If the input path ends in `Images/`, read `PROJECT.md` in its parent project folder when present. Use the project's recorded target and size defaults before asking for either.
- In Plan mode, present the plan without writing files. For a path-only prompt in other modes, prepare a plan unless the user has requested execution. Ask only about decisions that the workflow, project notes, and inspected inputs leave unresolved.
- For SVG Creation plans, state the size from the project or workflow as the working size and leave it out of the open questions. Use the workflow's nine-color default unless the user specifies a different limit. Count distinct colors after grouping features that share a layer. Before asking about a color change or merge, show the proposed colors and the features each covers. If the source image is still open, show a palette for each candidate.
- In SVG Creation plans and questions, show a visible swatch for each proposed color when the interface supports it. Pair it with a plain color name and the features it covers. Use an optional hex code alongside the name when inline swatches are unavailable.
